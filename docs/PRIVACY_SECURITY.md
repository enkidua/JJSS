# JJSS 개인정보·보안 안내

대상: JJSS를 쓰는 직업재활 실무자와 기관 담당자
기준: JJSS 3.1.0 (2026-09-24)
자세한 기술 점검표: [저장 데이터 감사](PRIVACY_STORAGE_AUDIT.md), [외부 AI 전송 감사](PRIVACY_OUTBOUND_AUDIT.md)

JJSS는 개인정보를 보호하기 위한 여러 장치를 갖추고 있지만, 기관의 개인정보 처리방침·생성형 AI 사용 지침·정보보안 지침을 대신하지 않습니다. JJSS를 쓴다고 해서 법령 준수가 자동으로 보장되지는 않으니, 기관 지침을 함께 확인해 주세요.

---

## 1. 데이터는 어디에 저장되나요?

JJSS는 인터넷 서버가 아니라 **이 PC 안**에 데이터를 저장합니다.

| 저장 위치 | 내용 |
|---|---|
| 앱 데이터 폴더 (Windows: `%APPDATA%\jjss`, macOS: `~/Library/Application Support/jjss`) | 이용자·사업체·사례문서·직업훈련·지출 기록, 설정, 암호화 키 파일 |
| JJSS 문서 폴더 (기본 `문서\JJSS`, 이전 버전에서 D 드라이브를 쓰던 PC는 `D:\JJSS`) | 사용자가 저장한 PDF·DOCX·PNG·CSV 문서와 백업 파일 |

JJSS는 사용 통계·오류 수집·추적 기능을 넣지 않았습니다.

## 2. 어떤 데이터가 암호화되나요?

앱 데이터 폴더에 저장되는 업무 데이터 중 **사람을 알아볼 수 있는 정보**는 암호화해서 저장합니다.

- **이용자:** 이름, 구직자 ID, 연락처, 주소, 생년월일, 나이, 장애유형·중증도, 희망 조건, 상태, 추천기관, 비고, 사진
- **사례문서:** 상담일지, 사례회의록, 직업재활계획서, 직업평가 결과, 고용지원 기록, 지원고용 회차(계좌·연락처 포함), 직업평가 회차·검사 기록·공식 결과지 확인값·직업평가보고서, 이용자 이름
- **직업훈련:** 훈련생 이름·메모·사진, 출결, 개인별 진행 기록, 상담·평가·현장 기록, 담당자
- **사업체:** 담당자 이름·연락처 (회사명·직무 같은 일반 정보는 암호화하지 않음)
- **지출:** 적요, 비고, 거래처, 카드 끝자리, 승인번호 (금액·날짜는 예산 계산용으로 암호화하지 않음)
- **설정:** AI 서비스 API 키

암호화하지 않는 것은 기록 번호, 문서 종류, 저장 시각처럼 사람을 알아볼 수 없는 정보뿐입니다. 예전 버전에서 암호화 없이 저장된 기록은 앱을 실행하면 백그라운드에서 자동으로 암호화 형식으로 바뀝니다. 이때 기존 데이터를 지우지 않습니다.

## 3. 암호화 키는 어디에 보관되나요?

JJSS는 무작위로 만든 256비트 키로 데이터를 AES-GCM 방식으로 암호화합니다. 이 키 자체는 **운영체제 보안 저장소로 한 번 더 잠가서** 앱 데이터 폴더에 파일(`jjss-data-key.bin`)로 둡니다. 잠기지 않은 키는 어디에도 저장하지 않습니다.

운영체제 보안 저장소를 쓸 수 없는 상황이면, 설치된 JJSS는 **새 개인정보 저장을 막고** 이렇게 안내합니다.

> 운영체제 보안 저장소를 사용할 수 없어 개인정보를 안전하게 저장할 수 없습니다. 앱을 재실행하거나 운영체제 보안 설정을 확인해 주세요.

키를 불러오지 못하면 기존 데이터는 지우지 않고 그대로 둡니다("보안 키를 불러오지 못했습니다. 기존 데이터를 삭제하지 않았습니다.").

## 4. Windows: 사용자 계정 보호 기능(DPAPI)

Windows에서는 **Windows 사용자 계정 보호 기능(DPAPI)** 으로 키를 잠급니다. 같은 PC의 같은 Windows 계정으로 로그인했을 때만 키를 풀 수 있습니다.

- 다른 Windows 계정이나 다른 PC로 앱 데이터 폴더를 복사하면 데이터를 읽을 수 없습니다. 이것은 의도된 동작입니다.
- Windows 계정 비밀번호를 관리자가 강제로 재설정하거나 Windows를 새로 설치하면 키를 잃을 수 있습니다. 그래서 **정기적인 암호화 백업**이 중요합니다.

## 5. macOS: Keychain

macOS에서는 **macOS Keychain(키체인)** 으로 키를 잠급니다. 처음 실행할 때 키체인 접근을 묻는 창이 뜨면 "항상 허용"을 눌러 주세요.

- 공개 배포용 맥 설치 파일은 Apple 개발자 인증서 서명과 공증(notarization)을 거쳐야 업데이트 후에도 키체인 접근이 안정적으로 유지됩니다. 현재 3.1.0 맥 빌드는 서명·공증 전 상태입니다.

## 6. 외부 AI로 어떤 데이터가 전달되나요?

AI 기능을 실행하면 **비식별화된 업무 내용**이 설정에서 선택한 AI 제공업체로 전송될 수 있습니다. JJSS가 사용하는 제공업체는 다음과 같습니다.

| 제공업체 | 쓰는 기능 |
|---|---|
| Google Gemini | 문서 작성·분석, 문서 질의응답, 직업평가 분석, 영수증 정리, 이미지 생성 |
| OpenAI | 설정에서 선택한 경우 문서 작성·분석 |
| Anthropic Claude | 설정에서 선택한 경우 문서 작성·분석 |
| Google Vision | 문서 OCR, 이용자 등록 OCR, 영수증 OCR |

AI 기능을 쓰지 않으면 업무 내용은 외부로 전송되지 않습니다. API 키 연결 확인은 업무 내용을 보내지 않습니다.

직업평가 "평가 진행"에서 AI를 쓰는 곳은 두 군데입니다. **공식 결과지 읽기**는 PDF에서 뽑은 글을 가려서 보내고 원본은 보내지 않습니다(스캔본은 매번 따로 확인합니다). **해석 제안**은 수치·비교 결과·관찰 항목 이름만 보내며 이름·메모·파일 이름은 보내지 않습니다. 검사 실시 기록과 보고서 작성 자체는 AI 없이도 그대로 쓸 수 있습니다.

## 7. 무엇을 비식별화하나요?

텍스트에 포함된 주요 직접식별정보를 **이 PC 안에서 먼저** 가린 뒤 전송합니다.

| 항목 | 처리 |
|---|---|
| 이름 (등록된 이용자·사업체 담당자, 현재 작업과 관련된 훈련생·직무지도원·담당자, "이름:", "○○ 님" 같은 표현) | `⟦이름1⟧` 같은 표시로 바꿈 |
| 전화번호, 주민등록번호, 외국인등록번호, 이메일, 생년월일 | 표시로 바꿈 |
| 나이 | "30대"처럼 연령대로 바꿈 |
| 상세 주소 | 시·군·구까지만 남김 |
| 의료기관 이름, 의사 이름, 진단·입원일 | 표시로 바꿈 (진료과·장애유형·중증도는 업무에 필요해 남김) |

AI 응답이 돌아오면 `⟦이름1⟧` 같은 표시만 **이 PC 안에서** 원래 이름으로 되돌립니다. 무엇을 무엇으로 바꿨는지 적은 대응표는 외부로 보내지 않습니다. 이전 대화 내용도 같은 방식으로 가려서 보냅니다.

이미지 생성 요청의 문구도 가려서 보내고, 만들어진 이미지에는 실제 이름을 자동으로 넣지 않습니다.

## 8. 첨부파일은 어떻게 처리되나요?

- **글자가 들어 있는 PDF:** PC 안에서 글자만 추출해 비식별화한 뒤 그 글만 보냅니다. PDF 원본은 보내지 않습니다.
- **스캔한 PDF나 사진(JPG·PNG 등):** 파일 안의 글자를 PC에서 가릴 수 없기 때문에 자동으로 보내지 않습니다. 보내야 할 때는 매번 아래 확인창이 뜨고, 기본값은 [취소]입니다.

> 이 파일은 이미지/PDF 원본이 Google Gemini로 전송됩니다. 파일에 이름, 연락처 등 개인정보가 포함되어 있는지 확인해 주세요. [원본 파일 전송] [취소]

- 이 확인은 "AI 사용 안내"나 "다른 제공업체 자동 전환" 설정과 **별개**입니다. 앞의 두 가지를 허용했더라도 원본 파일은 매번 따로 확인합니다.
- 첨부파일이 있는 요청은 한 제공업체가 실패해도 **다른 제공업체로 자동으로 넘기지 않습니다.**
- 큰 파일(14MB 초과)은 Google의 임시 저장소에 올린 뒤 처리가 끝나면 바로 삭제를 요청합니다.

## 9. 백업은 어떻게 보호되나요?

- 새 백업은 **비밀번호로 암호화하는 것이 기본**입니다(PBKDF2-SHA256 310,000회 + AES-GCM).
- 비밀번호는 어디에도 저장하지 않습니다. **비밀번호를 잊으면 백업을 복구할 수 없습니다.**
- 암호화하지 않은 백업은 "고급 옵션"에서 경고를 확인하고 체크해야만 만들 수 있습니다. 이 파일에는 개인정보가 평문으로 들어가니 보안이 확보된 저장장소에서만 쓰세요.
- 백업에는 AI 서비스 API 키가 들어가지 않습니다. 새 PC에서 복원한 뒤 API 키는 다시 입력해야 합니다.

## 10. 내보낸 PDF·DOCX·PNG·CSV는 주의해 주세요

JJSS에서 저장한 문서 파일은 **일반 파일**이라 암호화되지 않습니다. 앱 데이터 폴더의 암호화가 이 파일들에는 적용되지 않습니다.

- 내보낸 문서에는 개인정보가 포함될 수 있습니다. 기관의 보안 폴더나 암호화된 저장장소에 보관해 주세요.
- 메일·메신저로 보낼 때는 기관 지침에 따라 암호를 걸거나 필요한 부분만 공유해 주세요.
- 파일 이름에는 이용자 이름을 넣지 않도록 만들어져 있습니다.

## 11. PC를 옮길 때는

앱 데이터 폴더를 복사하는 방법은 **동작하지 않습니다**(키가 원래 PC·계정에 묶여 있음). 아래 순서로 옮기세요.

1. 기존 PC의 JJSS → 설정 → 파일·백업 → **암호화 백업 만들기**
2. 새 PC에 JJSS 설치
3. 새 PC의 JJSS → 설정 → 파일·백업 → 복원 → 백업 비밀번호 입력
4. AI 서비스 API 키 다시 입력

앱을 제거해도 앱 데이터 폴더는 지워지지 않습니다. PC를 폐기하거나 다른 사람에게 넘길 때는 앱 데이터 폴더와 JJSS 문서 폴더를 기관 절차에 따라 삭제해 주세요.

## 12. 보안의 한계

JJSS는 운영체제 보안 저장소와 AES-GCM을 이용하여 로컬 데이터를 보호하고, 텍스트에 포함된 주요 직접식별정보를 로컬에서 비식별화한 뒤 전송합니다. 그래도 아래 한계가 있습니다.

- **비식별화는 규칙 기반입니다.** 등록되지 않았고 "이름:", "님" 같은 단서도 없는 제3자의 이름, 특이한 표현은 가려지지 않을 수 있습니다. AI에 보내기 전 입력 내용을 한 번 확인해 주세요. 사건 경위처럼 내용만으로 사람을 알아볼 수 있는 정보도 남을 수 있습니다.
- **원본 첨부파일을 보내기로 확인하면**, 그 파일 안의 개인정보는 가려지지 않은 채 전송됩니다.
- **AI 제공업체의 데이터 처리**(보관 기간, 학습 사용 여부 등)는 각 제공업체의 약관과 기관의 계약 조건을 따릅니다. 기관 지침을 확인해 주세요.
- **로그인한 Windows·macOS 계정이 탈취되면** 그 계정으로 JJSS 데이터에 접근할 수 있습니다. PC 잠금, 계정 비밀번호, 백신 등 기본 보안 수칙을 지켜 주세요.
- **화면·인쇄물·내보낸 파일**은 JJSS 밖에서 관리해야 합니다.
- **복호화 키는 앱 화면 쪽 메모리에도 올라옵니다.** 운영체제 보안 저장소에서 꺼낸 키를 화면 프로그램이 받아
  암호를 풀기 때문입니다. 키는 다시 꺼낼 수 없는 형태로 다루고 원시 값은 쓰자마자 지우지만,
  앱 화면에 침입할 수 있는 취약점이 생기면 그 경로로 데이터를 읽힐 수 있습니다.
  외부 페이지 이동 차단·스크립트 실행 제한(CSP)·샌드박스로 그 가능성을 낮춰 두었습니다.
- 맥 설치 파일은 아직 Apple 서명·공증 전이라, 공개 배포 전에 서명·공증이 필요합니다. Windows 설치 파일도 현재 코드서명 없이 만들어져 설치할 때 경고가 뜹니다.
