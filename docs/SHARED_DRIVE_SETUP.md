# 공유 저장소(기관 공유 드라이브) 관리자 설정 안내

JJSS의 사례관리 기록을 기관 Google Workspace 공유 드라이브에 암호화해 두고 여러 직원 PC가 함께 쓰는 선택 기능입니다. 기본은 꺼져 있습니다. 아래 1~4는 Workspace 관리자가 한 번만 하면 됩니다.

## 1. 공유 드라이브 만들기

1. Google 드라이브 → 공유 드라이브 → 새로 만들기. 이름 예: `JJSS 사례관리`.
2. **구성원:** 사례관리 담당 그룹(예: `employment-team@기관도메인`)만 "콘텐츠 관리자" 또는 "참여자"로 추가합니다. 개인 계정·기관 밖 계정은 넣지 않습니다. JJSS는 "참여자" 이상이어야 파일을 만들 수 있습니다.
3. **공유 드라이브 설정**(공유 드라이브 이름 옆 ▾ → 공유 드라이브 설정)에서 모두 끕니다.
   - 조직 외부 사용자의 액세스 허용 → 끔
   - 구성원이 아닌 사용자에게 액세스 권한 허용(파일 공유) → 끔
   - 뷰어 및 댓글 작성자의 다운로드·인쇄·복사 허용 → 끔

4. **관리 콘솔(권장):** 보안 → 인증 → 2단계 인증에서 사례관리 담당 조직 단위에 **2단계 인증 강제**. 드라이브 감사 로그 보존 기간을 기관 규정에 맞춥니다. 구글 로그인 계정이 곧 공유 저장소 접근 권한이므로, 계정 보안이 곧 기록 보안입니다.

JJSS는 켤 때와 하루 한 번 이 설정을 확인합니다. 링크 공유·기관 밖 구성원·다른 도메인 공유가 있으면 동기화를 멈춥니다. 구성원 목록은 관리 권한이 있는 계정만 볼 수 있으므로, 일반 직원 PC에서는 "구성원 목록 확인 못 함"(주의)이 보일 수 있습니다. 관리자 계정으로 한 번 점검해 두세요.

## 2. OAuth 클라이언트 만들기(기관 내부용)

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 기관 조직 아래에 프로젝트를 만듭니다(예: `jjss-shared-drive`).
2. API 및 서비스 → 라이브러리 → **Google Drive API** 사용 설정.
3. OAuth 동의 화면 → 사용자 유형 **내부(Internal)**. 앱 이름 `JJSS`, 지원 이메일은 관리자 메일. 범위는 `openid`, `email`, `.../auth/drive`.
   - 내부 앱이므로 구글 앱 심사가 필요 없고, 기관 도메인 계정만 로그인할 수 있습니다.
4. 사용자 인증 정보 → 사용자 인증 정보 만들기 → **OAuth 클라이언트 ID** → 애플리케이션 유형 **데스크톱 앱**.
5. 만들어진 **클라이언트 ID**(`….apps.googleusercontent.com`)와 **클라이언트 보안 비밀**을 직원 PC 설정에 넣습니다. 데스크톱 앱의 보안 비밀은 구글 정책상 완전한 비밀로 취급되지 않지만, JJSS는 이 PC의 운영체제 보안 저장소에 암호화해 둡니다. 로그인은 PKCE로 보호됩니다.

관리 콘솔에서 서드파티 앱 접근을 제한하고 있다면: 관리 콘솔 → 보안 → 액세스 및 데이터 제어 → API 제어 → 앱 액세스 관리에서 위 클라이언트 ID를 **신뢰함**으로 추가합니다.

## 3. 첫 PC(관리자)에서 켜기

설정 → 공유 저장소 → 공유 저장소 설정하기.

1. 안내를 읽고 동의 → 기관 도메인·클라이언트 ID·보안 비밀 입력.
2. 구글 로그인(브라우저 창) → 공유 드라이브 선택 → 보안 점검(막힌 항목이 없어야 다음으로 넘어감).
3. **새 기관 키 만들기** → 28자 코드를 종이 등에 적고 마지막 4자로 확인.
4. **기존 자료 올리기:** 이 PC 사본을 자동으로 만든 뒤 이용자·사례 기록을 암호화해 올리고, 올린 뒤 드라이브와 같은지 확인합니다. 읽지 못한(깨진) 기록은 올리지 않습니다. 중간에 끊기면 다시 누르면 이어서 합니다.
5. **공유 저장소 켜기.**

## 4. 다른 직원 PC에서 켜기

같은 순서로 하되, 3단계에서 관리자에게 받은 **기관 키 코드**를 입력합니다. 코드는 메일·메신저로 보내지 말고 직접 알려 주세요. 4단계에서 그 PC에 이미 있던 자료도 함께 올라가며, 같은 기록인데 내용이 다르면 "충돌", 이름+관리번호가 같은 이용자는 "같은 사람으로 보이는 이용자"로 따로 보여 줍니다(자동으로 합치지 않음).

## 운영 중

- **상태 표시:** 켜져 있으면 화면 오른쪽 아래에 동기화 상태가 보입니다. 오프라인이면 바뀐 내용을 모아 두었다가 다시 연결되면 올립니다.
- **충돌:** 설정 → 공유 저장소에서 "이 PC 것으로 / 드라이브 것으로"를 고릅니다.
- **격리:** 기관 키로 열리지 않거나 속성과 내용이 맞지 않는 드라이브 파일입니다. 누군가 드라이브에서 파일을 직접 고쳤을 수 있습니다. 확인 뒤 "이 PC 기록으로 다시 쓰기".
- **퇴사·코드 유출:** 설정 → 공유 저장소 → 관리자: 기관 키 → **기관 키 바꾸기**. 드라이브 기록 전체를 새 키로 다시 암호화합니다. 다른 PC는 새 코드를 넣어야 이어서 씁니다. 퇴사자 계정은 공유 드라이브 구성원에서도 빼 주세요.
- **백업 복원:** 복원하면 동기화가 멈추고 "복원본으로 드라이브 덮기 / 드라이브 것으로 이 PC 덮기"를 고르게 합니다.
- **끄기:** 이 PC 자료는 그대로 두고 주고받기만 멈춥니다. 로그아웃하면 이 PC의 구글 토큰(폐기 요청 포함)과 기관 키를 지웁니다.

## 보안 요약

| 항목 | 방식 |
|---|---|
| 내용 | 이 PC에서 기관 키로 AES-256-GCM 암호화(레코드 id·키 id를 인증 데이터로 묶음). 삭제 여부·버전도 암호문 안에 둠 |
| 파일 속성(평문) | 레코드 id, 버전, 수정 시각, 수정한 직원 메일, 내용 지문(HMAC) — 이름·연락처 없음 |
| 토큰·비밀 | 운영체제 보안 저장소로 암호화, 화면(렌더러)에 전달하지 않음 |
| 접근 범위 | 고른 공유 드라이브 하나(코드에서 파일마다 드라이브 id 확인) |
| 끈 상태 | 구글 요청 0건 |

1차 범위 밖(2단계 예정): 사진·첨부 파일(사례 기록의 `photoFileNames`는 각 PC의 JJSS 폴더에 그대로 있고 올라가지 않습니다), 직업훈련·예산, 오래된 연도의 지연 내려받기, 묘비(삭제 표시) 파일의 주기적 정리. 올리기 직전 사본은 `사용자 데이터 폴더/shared-drive-backups`에 저장소 폴더를 통째로 복사한 것이라, 되돌리려면 앱을 끈 뒤 `IndexedDB` 폴더를 바꿔 넣어야 합니다(일반 복원은 설정 → 파일·백업의 `.jjss` 백업을 쓰세요. 올리기 전에 한 번 만들어 두기를 권장합니다).

알려진 한계: 기관 키를 가진 직원은 모든 기록을 읽고 고칠 수 있습니다(권한 구분 없음). 아직 그 기록을 받은 적 없는 새 PC는 같은 기관 키로 만든 예전 내용을 최신과 구별하지 못합니다. 실제 구글 계정·공유 드라이브로 하는 확인은 기관 OAuth 클라이언트가 준비된 뒤 관리자 PC에서 해야 합니다.
