## 실행한 검증

- 수정 후 `npm.cmd run test:all` 통과(타입 검사 포함).
- 수정 후 `npm.cmd run build` 통과. 번들 크기/Browserslist 경고는 남아 있음.
- `npm.cmd run check:build` 통과(최종 재빌드에 대해서도 재확인).
- `npm.cmd run test:usability` 통과: 주요 10개 경로, 메뉴, 초안 보호, 후속업무, 현황판, 지원고용, 평가 화면, 모바일 메뉴. 격리된 브라우저/합성 데이터, 외부 API 차단.

## 18차 점검 · 3.2(API 키 오류 표시·자동 업데이트)와 공유 저장소 (2026-10-29)

계획서 `docs/2026-10-29-auto-update-shared-storage-api-key-plan.md`의 세 항목을 구현했다. C·A는 3.2 배포 브랜치 `codex/jjss-v3-stabilization`, B(공유 저장소)는 계획대로 별도 브랜치 `codex/shared-drive-sync`(3.2 위에 쌓음)에 있다.

**C. API 키 오류 표시(8b19eb5):** 붙여 넣은 키를 정리(따옴표·Bearer·`NAME_KEY=` 제거)하고 형식으로 제공업체를 판별해, 다른 칸에 넣은 키(예: OpenAI 칸의 Gemini 키)는 바로 경고하고 "○○ 칸으로 옮기기"를 보여 준다. 저장 직후 연결을 자동 확인해 칸마다 확인됨·실패·미확인을 표시한다(키 원문 대신 SHA-256 지문으로 기억, 네트워크 오류는 실패로 기록하지 않음). AI 요청 중 키가 거부되면 해당 칸 안내와 설정 바로가기를 띄운다(30초에 한 번).

**A. 자동 업데이트(6e8e5c5·8d08856·737d662):** electron-updater로 GitHub `enkidua/JJSS` 공개 Releases를 켜고 10초 뒤·6시간마다 확인한다. 알림만 하고 내려받기·설치는 사용자가 누를 때만. 설치 직전 저장소 사본(update-backups, 최근 2개). Windows는 내려받은 설치파일이 같은 서명자(JJSS)여야 설치되며, 서명자가 고정되지 않은 빌드는 업데이터를 끈다(보안 검토 반영). macOS는 공증 전까지 내려받기 페이지 안내만. 빌드는 게시하지 않는다(`--publish never`).

- 오프라인 우선(올릴 목록), 변경 목록 토큰으로 바뀐 것만 받기, 낙관적 잠금 충돌은 사용자가 고름, 삭제는 봉인한 묘비로만 전파(드라이브에서 지워도 다른 PC 자료는 지우지 않음), 편집 중 표시(30분), 키 교체.

- 설정 마법사: 안내·동의 → 관리자 설정 → 로그인 → 공유 드라이브 → 보안 점검(링크 공유·기관 밖 구성원·개인 드라이브·다른 도메인은 차단) → 기관 키(생성 후 끝 4자 확인 / 입력 후 드라이브와 대조) → **기존 자료 올리기**(사본 → 올리기·받기·합치기 → 드라이브와 같은지 검증, 읽지 못한 기록은 올리지 않음, 끊기면 이어서) → 켜기. 켠 뒤 상태·충돌·격리·같은 사람으로 보이는 이용자 합치기·복원 뒤 기준 고르기·키 보기/바꾸기, 화면 오른쪽 아래 상태 표시, 직업평가·지원고용 회차의 "편집 중" 표시.

**보안(공유 저장소)**
- **내려받기 상한 없음(높음):** main이 파일 전체를 메모리에 올려, 드라이브 구성원(기관 키 불필요)이 레코드 파일을 수 GB로 바꿔치기하면 모든 PC가 같은 파일을 받다 메모리 부족으로 재시작을 반복했다. 내려받기도 20MB 상한(Content-Length와 실제 수신량 모두)으로 끊고 `DRIVE_TOO_LARGE`, 엔진은 그 파일만 격리하고 나머지는 계속 받는다.

- **새 키 수용 기준(중간):** 다른 PC가 "새 기관 키 코드"를 넣을 때 키 확인 표식만 봤다(표식은 구성원 누구나 교체 가능). 옛 키로 봉인한 교체 증명이 있으면 그 증명이 가리키는 키만 받는다. 새 PC(옛 키 없음)는 표식만으로 확인할 수밖에 없어 문서에 "코드는 관리자에게 직접" 규칙과 "퇴사자는 구성원에서 먼저 제외 → 키 교체" 순서를 적었다.
- **키 교체 중 다른 PC의 수정(낮음·중간):** 교체는 목록을 받은 시점의 속성으로 열어 그 사이 올린 파일이 격리됐고, 옛 키 PC의 올리기는 격리·충돌로 끝났다. 파일마다 최신 속성을 다시 받고, 다시 봉인한 봉투에 `rotated`(내용은 바로 전 버전과 같음) 표시를 넣어, 옛 키 PC는 교체 중 올리기를 격리 없이 미루고 새 키를 넣은 뒤 자기 수정을 충돌이 아니라 그 위에 올린다.
- **그 밖에:** Linux `basic_text` 보안 저장소 거부(dataKey와 동일 기준), 한 기록의 올리기 실패(이름·속성 형식·크기)가 전체 올리기를 멈추지 않고 격리 목록에만 남김, 깨진 `createdAt`으로 네 자리 아닌 연도 폴더를 만들지 않음, 429·5xx는 "오프라인"이 아니라 다음 주기 재시도로 표시, 옛 버전이 새 상태 저장소를 열 때 안내문.
- 검토했으나 그대로 둔 것: 지문(HMAC)이 결정적이라 "내용 동일성"은 드러남(키 없이 내용 추정 불가), `editingBy`는 표시용(판단 근거 아님), 연도 폴더로 연도별 건수가 보임, `updatedBy` 메일 평문(드라이브 활동 기록과 같은 수준).

**보안(앱 전체)**
- **업데이트 서명 검증 지문 고정(중간):** electron-updater 기본 검증은 Status=Valid와 CN("JJSS")만 보고, PowerShell이 막힌 PC에서는 검증을 건너뛰었다(통과 처리). 자체 검증으로 바꿔 인증서 지문(SHA-1, `ALLOWED_SIGNER_THUMBPRINTS`)까지 비교하고 검증 도구 실패는 거부한다. `check-win-signing`이 빌드 전에 PFX 지문이 목록에 있는지 확인하고, 인증서 갱신 순서(새 지문을 먼저 배포)를 `WINDOWS_INTERNAL_SIGNING.md`에 적었다. PFX를 OneDrive 동기화 폴더 밖에 두라는 안내 포함(코드로는 못 막음).
- **다른 제공업체 형식의 키 전송(중간·낮음):** OpenAI 칸에 Claude 키를 저장하면 그 비밀값이 api.openai.com으로 나갔다(경고만 하고 저장·전송). 전송 직전(`createGoogleAIClient`·`callOpenAI`·`callAnthropic`·Vision)에서 형식 불일치 키를 거부하고, 전환 후보에서도 "키 없음"으로 뺀다. 저장은 막지 않는다(옮기기 안내).
- **렌더러 권한 요청:** 기본값이 허용이라 카메라·마이크·위치·알림 요청을 묻지 않고 허용했다(현재 공격 경로 없음). 클립보드 쓰기만 허용하고 나머지는 거부.
- 문서화만: 정보 자료(InfoMate)·예산 사업 목록은 평문(개인정보를 적지 말라는 안내), 기본 저장 위치가 OneDrive "알려진 폴더 이동"에 걸릴 수 있음, 이름 사전은 선택한 이용자의 기록 속 이름까지만(다른 회차의 직무지도원은 규칙 기반).
- 확인했고 문제 없던 것(검토 기록): Electron 창 플래그·내비게이션 차단·외부 열기 제한·단일 인스턴스, preload 채널 고정·발신자 검증, 파일 서비스 경로·시그니처·크기 검사, 데이터 키 DPAPI/Keychain·덮어쓰기 금지, 백업 PBKDF2 310k·복원 크기/깊이/프로토타입 오염 방어, 외부 전송은 세 모듈뿐이고 텔레메트리·CDN 없음, XSS 싱크 없음, OAuth state·PKCE·`hd`·`email_verified`·토큰 비노출, IPC 인수 검증·드라이브 id 대조.

**기능 연동**
- **편집 보호 범위(높음):** "열어 둔 기록은 덮지 않는다"(19차)가 직업평가 회차·지원고용 회차 두 화면에만 있었다. 이용자 수정 창, 상담일지·사례회의록·재활계획(사례관리 단계·후속 기록), 면접일지·직무분석지, 직업평가 저장 문서 수정, 매칭 의견에도 편집 표시·보호를 넣었다. 후속 기록 목록은 마지막으로 포커스한 항목을 등록한다.
- **삭제 안내:** 다른 PC의 삭제가 이 PC에 반영되면 "다른 PC에서 지운 기록 N건" 알림(직업훈련 명단에서 훈련생이 빠지는 이유도 이것).
- **지출 연결:** 회차에 연결된 지출이 이 PC 예산 관리에 하나도 없으면(다른 PC의 예산) 초안을 다시 만들거나 연결을 지우지 않는다(전에는 같은 사업 id가 있으면 연결을 비워 드라이브로 전파).
- **이름 기준 재연결:** `migrateCaseDocumentSeekerIds`가 id로 못 찾은 문서를 이름이 같은 한 명에게 붙였다. 공유 저장소가 켜져 있으면(이용자가 아직 안 왔거나 격리·충돌 중일 수 있음) id가 있는 문서는 이름으로 붙이지 않는다. 데이터 저장소가 동기화 모듈을 직접 불러오지 않도록 `localDB.isSharedDriveActive()`로 둔다.
- **충돌 화면:** 160자 요약 아래 "전체 내용 나란히 보기"(JSON content도 줄 단위로 펼침)를 넣어 고르기 전에 끝까지 비교하고 복사할 수 있다.
- 문서화만: 사업체·구인 목록, 정보 자료는 1차 범위 밖(다른 PC에서 사업체 선택란이 비어 보임), 복원본 기준 선택은 드라이브의 삭제도 되살림, 시계 차이에 따른 편집 중 표시 오차.
