# 2026-05-08 예산 정리, 직업훈련 점검, 위기대응 복구

## 작업 범위
- 예산 화면을 지출 등록, 지출 목록, 선택 항목 기반 지출품의서 생성 중심으로 단순화했다.
- 직업훈련 기능은 기존 `trainingState` 저장 구조와 export/import 포함 여부를 확인하고 유지했다.
- 위기대응 시뮬레이터를 업무 지원 도구 내부 카드로 복구했다.
- 메뉴/라우트, DB 버전, Gemini 모델 정책은 변경하지 않았다.
- 인포메이트, 커뮤니티, 인트라넷은 다시 연결하지 않았다.

## 예산 화면
### 유지한 기능
- 지출 등록/수정/삭제
- 지출 목록 즉시 반영
- 앱 재시작 후 IndexedDB `expenses` store에서 지출 목록 조회
- 검색, 카테고리 필터
- 선택한 지출 항목 기준 지출품의서 미리보기/인쇄/PDF 저장
- 합계, 날짜, 예산과목, 세부사업명, 품명/내용, 거래처, 결제방법, 비고 표시
- PDF/인쇄 실패 시 원본 지출 데이터 유지

### 제거한 UI
- 영수증 OCR/이미지 업로드 자동 입력 UI
- OCR 항목 선택 모달

### 제거 이유
- 지출 등록/목록/품의서 생성의 핵심 흐름과 분리되어 있었다.
- OCR/AI 파싱 실패 시 예산 입력 흐름을 불안정하게 만들 수 있었다.
- 수기 입력 기반 지출 등록 기능과 중복되고, 현재 단계의 안정화 목표와 맞지 않았다.

## 직업훈련
### 동작하는 기능
- 직업훈련 메뉴 접근
- 훈련실 생성/수정/삭제
- 등록 이용자 기반 훈련실 배정
- 출석 기록
- 연간 프로그램 진도 표시 및 기록
- 훈련계획 생성
- 훈련 상담일지 생성 및 누적
- 훈련 정기평가 생성
- 현재 내용 기반 보완 기능 유지
- 자동 저장 및 앱 재시작 후 조회

### 저장 구조
- IndexedDB 기존 store: `trainingState`
- 대표 문서 id: `work-training`
- 저장 데이터:
  - `rooms`
  - `attendanceBook`
  - `progressYear`
  - `progressBook`
  - `trainingRecords`
  - `updatedAt`
- `exportAllData/importAllData`는 `STORES` 배열 전체를 순회하므로 `trainingState`도 포함된다.

## 위기대응 시뮬레이터
### 접근 경로
- 업무 지원 도구 → 위기대응 시뮬레이터

### 복구 내용
- 기존 시나리오 라이브러리/시뮬레이션/매뉴얼 보기 유지
- 직접 입력 위기대응 안내 추가
- 출력 항목:
  - 상황 요약
  - 즉시 확인할 위험 요소
  - 초기 대응
  - 보호자/기관/응급 연락 판단
  - 기록해야 할 내용
  - 사후 지원계획

### AI 실패 fallback
- AI 생성 실패 시 기본 대응 템플릿을 즉시 표시한다.
- 의료적/법적 판단은 단정하지 않도록 안내한다.
- 긴급 상황은 119, 보호자, 기관 지침을 우선하도록 안내한다.

## 매칭 의견 저장 보완 유지
- `saveMatchingOpinion` 흐름은 유지했다.
- `jobId`가 없는 경우 `companyName + jobRole + location` 조합을 저장 키로 사용하도록 보강했다.

## 검증
- `npm run build` 통과
- 남은 경고: Vite 번들 청크 크기 경고가 유지된다.

## 남은 위험 요소
- 위기대응 직접 입력 AI 안내는 설정된 AI API 키가 없거나 실패하면 기본 템플릿으로 대체된다.
- 예산 OCR은 제거했으므로 향후 다시 넣으려면 별도 안정화된 OCR 입력 흐름과 실패 처리 설계가 필요하다.
- 번들 크기가 커지고 있어 추후 업무도구별 lazy loading을 검토하는 것이 좋다.
