# JJSS 직업평가 지원 기능(평가 워크벤치) 도입 계획

작성일: 2026-09-25
개정: 2026-09-25 (2차) — **규준(백분위) 계산은 구현하지 않는다.** 공단 온라인 프로그램이 결과를 입력하면 공식 결과지를 만들어 주므로, 앱은 **그 결과지를 읽어 해석**한다. 함께 **VE Assist 0.1.0의 구조를 JJSS로 이식**하는 것을 이 작업의 중심으로 둔다.

## 0. 한 줄 요약

직업평가 화면에 **"평가 진행"** 흐름을 추가한다. KEAD 손기능·다차원 양손협응 검사의 **실시 과정을 앱에서 기록**하고(타이머·수행량·오류·행동관찰), 공단 프로그램이 만든 **공식 결과지를 가져와 확인한 뒤**, 그 값을 근거로 해석·보고서·쉬운 설명을 만든다. **앱은 백분위를 계산하지 않는다.** AI는 판단하지 않고 초안만 낸다. 기존 3개 탭은 유지한다.

### 역할 분담 (이번 개정의 핵심)

| 하는 일 | 주체 |
|---|---|
| 검사 실시 기록 (타이머·수행량·오류·행동관찰·검사조건) | **JJSS** |
| 원점수 → 백분위 산출, 공식 결과지 생성 | **공단 온라인 프로그램** |
| 공식 결과지 읽기·검토·확정 | **JJSS** (평가사가 최종 확인) |
| 패턴 분석·해석 초안·보고서·쉬운 설명 | **JJSS** |

앱은 결과지에 **인쇄된 값을 그대로** 근거로 쓴다. 값을 새로 만들거나 바꾸지 않는다.

### 1-3. VE Assist에서 정정해 이식할 것

이식하면서 아래 두 가지는 **원본 코드를 그대로 옮기지 않고 고쳐서** 넣는다.

| # | VE Assist 현재 값 | JJSS 이식 값 | 이유 |
|---|---|---|---|
| 1 | `plate.maximum = 4`, `ruleStatus: 'SOURCE_CONFLICT'`, 합계 28 vs 표기 25 충돌 | **`plate.maximum = 1`, `ruleStatus: 'VERIFIED'`, 합계 25** | 요강 부록2와 공단 프로그램 화면이 `판 1/1`, `총합 17/25`로 일치한다. 충돌이 아니었다 |
| 2 | 다차원 `defaultDurationMs: 90_000` (관측값에서 추정) | 90,000ms 유지하되 **"공식 제한시간 1분 30초"로 표기** | 값은 같지만 근거가 추정이 아니라 요강이다. 화면 문구를 바꾼다 |

`claimQuality`의 "기록시간·수행량으로 전체 완료 추론" 금지 규칙은 **그대로 유지한다.** 분모가 확정되어도 "시간이 다 찼으니 전부 조립했다"는 추론은 여전히 금지다.

## 2. 규준(백분위)은 계산하지 않는다 — 공식 결과지를 읽는다

### 2-1. 방침

- **앱은 규준표를 내장하지 않고 백분위를 계산하지 않는다.** 공단 온라인 프로그램에 원점수를 입력하면 공식 결과지가 만들어진다. 앱은 그 결과지의 값을 **읽어서 저장**한다.
- 결과지에 인쇄된 백분위·평균·서술 문장은 **출처가 결과지임을 표시**해 저장한다(`origin: OFFICIAL_PDF`). 앱이 기록한 값(`DIRECT_ENTRY`)과 섞이지 않는다.
- 앱이 직접 기록한 원점수와 결과지 값이 **다르면 충돌(CONFLICT)로 표시**하고, 평가사가 어느 쪽을 쓸지 고른 뒤에야 해석에 들어간다. 자동으로 한쪽을 고르지 않는다.
- 해석·보고서·쉬운 설명은 **확정된 값만** 근거로 쓴다. AI가 백분위를 새로 만들거나 순위로 바꾸는 것은 `claimQuality`가 막는다.

### 2-2. 결과지에서 읽는 항목

| 검사 | 읽는 값 |
|---|---|
| 손기능 | 7조건 × (1·2·3회, 표기 평균), 결과지에 인쇄된 비교값·서술 문장, 피검자 표기 정보(성별·장애유형·우세손), 검사일·평가사 |
| 다차원 | 부품 7종 수행량과 각 분모, 표기 총 수행량·총 도구수, 기록시간, 인쇄된 비교값·서술 문장 |

읽기는 **PC 안에서 먼저** 한다. 글자가 들어 있는 PDF는 `localPdfText`로 추출하고, 구조화가 필요할 때만 비식별화한 텍스트를 AI에 보낸다. **PDF 원본은 보내지 않는다.** 스캔본은 기존 첨부 동의(동의 C) 절차를 그대로 따른다.

### 2-3. 결과지를 읽지 못해도 막히지 않는다

결과지가 없거나 읽기에 실패하면 **앱이 기록한 원점수만으로** 해석·보고서를 만들 수 있다. 이때 화면과 보고서에 `공식 결과지 미연결 — 앱 기록 기준`을 표시하고, 백분위가 필요한 문장은 만들지 않는다(`interpretationReadiness`가 PARTIAL로 내린다).

## 3. 사용자 흐름

기존 3개 탭은 유지하고 **"평가 진행"** 탭을 첫 번째로 추가한다. 이용자 선택은 화면 상단에서 한 번만 한다.

```
[평가 진행] 탭
 ├ 평가 회차 목록 (이용자별)
 └ 회차 상세 (단계 레일)
     ① 기본정보    회차 제목·목적·의뢰기관·평가유형(내관/이동)·평가일·평가사, 우세손 판정(질문 3문항 → 평가용지 18문항)
     ② 검사 실시   검사 선택 → 실시(타이머·수행량·오류·검사조건) → 시행 확정
     ③ 행동관찰    사건에서 만든 후보 반영/제외, 관찰 항목·검사조건 정리
     ④ 원자료 요약  공단 프로그램에 그대로 입력할 수 있는 형태로 정리(복사)
     ⑤ 결과지 가져오기  공단 공식 결과지 PDF 읽기 → 대조·충돌 확인 → 확정
     ⑥ 해석        패턴 + AI 해석 제안 채택/수정/제외
     ⑦ 보고서      직업평가보고서 작성 → 확정 → DOCX/PDF
     ⑧ 쉬운 설명   당사자용 결과 설명 (선택, 아직 없음)
```

### 검사 실시 화면 (핵심)

- **손기능**: 21시행을 조건별로 묶어 진행. 30초 타이머, 수행량 입력, 오류 빠른 기록, 재설명 횟수 카운터(2회 초과 경고), 중단 3회 시 "실패" 처리 안내.
- **다차원**: 1분 30초 1회. 종료 후 부품 7종 입력(분모 4·4·4·4·4·**1**·4), 총합 자동 계산(/25).
- 키보드 우선: Space 시작·일시정지, Esc 일시정지, ↑↓ 수행량, Enter 확정, F1~F4 빠른 오류, Ctrl+Z 취소, Ctrl+M 메모.
- 타이머는 `performance.now()` 기준. 화면을 벗어나면 자동 일시정지하고 남은 시간을 저장한다. 앱이 꺼졌다 켜지면 마지막 시행부터 복구한다.
- **2·3차 미실시 지원**: 각 시행을 "미실시"로 두고 사유를 남기게 하며, 평균은 실시한 회차만으로 계산하고 화면·보고서에 "n회 실시 평균"을 표기한다.

## 4. 보고서 — 기관 실제 서식 기준

|---|---|
| 머리 | 평가실시기관, 의뢰요청기관, 평가일, 평가유형(내관/이동), 성명, 생년월일, 연락처, 거주지, 장애유형/중증여부, 성별, 욕구 체크(직업흥미·직업적성·행동·구직욕구·적응수준·정서) |
| 평가목적 | 자유 서술 |
| 평가 도구(방법) | 평가영역 × 평가도구 표. 기본 영역: 사회진단(사회적응도), 신체적 능력, 심리진단(인지·언어 / 정서 및 성격), 직업흥미, 직업준비, 직업진단(손기능 / 작업활동) |
| 종합소견 및 직업재활방향 | 직업수준, 직업목표(당사자 및 보호자·지원자 목표), 직업적 강점 및 제한점(강점 / 제한점·고려사항 2단), 추천(적합 추천 직무 및 사유), 추천직무 |
| 끝 | 작성일, 직업평가사 서명란 |

### 4-2. 상세 페이지 (선택)

장애 및 진단이력 / 교육훈련 및 직업경력 / 생활적응능력 / 사회진단(행동관찰 포함) / 신체적 능력 / 심리진단 / 직업진단(손기능·다차원 결과표 — **결과지에서 읽은 값 그대로**).

### 4-3. 작성 방식

- 각 항목은 **자동 조립 문단 + 평가사 직접 서술** 2층. 평가사는 자동 문단을 제외할 수 있다. **AI가 전혀 없어도 직접 서술만으로 보고서를 완결할 수 있다.**
- 확정하면 **읽기 전용 스냅샷**이 되고, 수정은 새 버전으로 한다. 확정 후 원자료가 바뀌어도 출력은 변하지 않는다(`contentHash`).
- 출력은 DOCX(맑은 고딕, A4)와 PDF. 파일명에 이용자 이름을 넣지 않는다.

## 5. AI 사용 원칙

- 모든 AI 호출은 기존 관문 `prepareAIOutboundText`를 통과한다. 이름·생년월일·연락처·기관명·평가사명을 뺀 **근거 패키지**(수치·패턴·관찰 라벨)만 보낸다. 자유 메모는 기본 미전송이며 평가사가 "AI 서술에 포함"을 켠 항목만 보낸다.
- 근거 ID는 `fact_0`·`observation_1`·`pattern:hand:SMALL`처럼 **사람을 가리키지 않는 값**만 내보낸다. 실제 기록 ID와 결과지 원문 라벨은 PC 안의 대조표(`references`)에만 두고 전송하지 않는다.
- AI 응답은 JSON 스키마로 받고, `claimQuality` 검사 후 **항상 "제안" 상태**로 저장한다. 평가사가 채택·수정·제외해야 문서에 들어간다.
- **AI 금지 목록** (VE Assist `claimQuality` 이식): 취업 가능/불가능, 직무 적합·부적합, 특정 직업 추천, 의학적 진단, **백분위·순위 생성**, 근거 없는 수치 인용, 검사조건만으로 능력 추론, "미평가 = 문제없음", 기록시간으로 전체 완료 추론.
- 재시도·전환 규칙(`MAX_ATTEMPTS_PER_JOB=3`, `MAX_ATTEMPTS_PER_PROVIDER_PER_JOB=1`, `MAX_AUTOMATIC_RETRIES=0`)은 그대로 둔다.

## 6. 데이터 모델과 저장

새 IndexedDB store와 DB 버전 변경 없이 `caseDocuments`에 JSON 문서로 저장한다(지원고용 회차와 같은 방식). 문서 종류 4개를 추가한다.

| type | 단위 | 내용(전체 암호화) |
|---|---|---|
| `ve_episode` | 평가 회차 | 기본정보, 우세손 판정, 연결 이용자, 상태, 연결 문서 ID |
| `ve_session` | 검사 세션 | 검사 종류, 시행별 수행량·오류·미실시 여부, 사건, 관찰, 검사조건, 타이머 체크포인트, 확정 정보 |
| `ve_source_document` | 공식 결과지 | 파일 메타·SHA-256, 추출 이력, 검토 이슈, **확정된 결과지 값**. PDF 원본은 저장하지 않음 |
| `ve_report` | 보고서 1버전 | 요약본·상세 섹션(자동 문단 + 평가사 서술), 확정 스냅샷(contentHash), 이전 버전 ID |

- 문서마다 `seekerId`·`seekerName`을 넣어 현황판 타임라인과 이용자 삭제에 자동으로 잡히게 한다.
- 실시 중 저장: 수행량·오류·확정은 즉시, 메모는 650ms 지연, 타이머 남은 시간은 5초마다.
- 확정 스냅샷은 `normalize`에서 변경을 거부한다.
- **이 문서들은 AI 컨텍스트(`clientContextService`)에서 제외한다.** 지원고용 문서와 같은 처리다.

### 남은 판단
