## A. 직업훈련·직업평가·고용지원으로 넘어갈 때 번쩍임

### 원인
1. 1차 수정에서 페이지를 `React.lazy`로 나눴다. 메뉴를 처음 누르면 해당 페이지 파일을 내려받는 동안 "화면을 불러오는 중입니다…" 한 줄이 잠깐 보였다가 본문으로 바뀐다. 이 높이 차이가 번쩍임으로 보인다.
2. 세 페이지(`WorkTraining`, `VocationalEvaluation`, `WorkMate`)가 framer-motion `initial={{ opacity: 0 }}` 진입 애니메이션을 쓰고 있어, 파일을 받은 뒤에도 한 번 더 깜빡인다.
3. `Layout`이 경로가 바뀔 때 `scrollTo(0)`와 포커스 이동을 하는데, 1과 겹치면 두 번 움직이는 것처럼 보인다.

## B. 직업재활 현황판 재설계 (한 사람의 상황 대시보드)

### 문제
현재 `/overview`는 후속 일정·목표 추적·적응지원·직무 비교·당사자 계획 **입력 폼 5개**가 한 페이지에 쌓여 있어, "상황을 보는 화면"이 아니라 또 하나의 입력 화면이 됐다. 같은 정보가 고용지원·직업훈련 화면과 따로 관리되어 어디에 무엇을 적었는지 헷갈린다.

### 원칙
- 현황판은 **읽기 전용 대시보드**. 입력 칸을 두지 않는다.
- 각 카드의 "입력하기/이어서 작성" 버튼은 **실제 서비스 화면**(직업평가·직업훈련·고용지원)의 해당 탭으로 이용자를 넘겨 이동한다.
- 예외 하나: "현재 상황 정리" 메모(담당자가 한 문단으로 쓰는 요약)만 현황판에서 저장한다. 이건 다른 화면에 대응하는 곳이 없기 때문이다.
- 데이터 구조(`RehabWorkflowData`, `caseDocuments`, `trainingState`)는 바꾸지 않는다. 입력 UI의 위치만 옮긴다.

### 화면 구성 (위에서 아래로)
1. **이용자 선택 + 머리글**: 이름, 장애유형, 등록일, 담당자. 현재 단계 배지: `평가 → 훈련 → 지원고용 → 취업 → 적응지원` 중 어디인지(문서·기록 존재 여부로 자동 판정).
2. **3개 상태 카드(한 줄)**
   - **직업평가**: 최근 평가일, 결과분석/종합소견 문서 수, 마지막 소견 첫 2줄. 버튼 "평가 화면에서 이어서 작성".
   - **직업훈련**: 배정 훈련실, 훈련기간, 출석률(실제 기록만), 최근 상담일, 마지막 훈련계획 요약. 버튼 "직업훈련 화면으로".
   - **고용지원**: 매칭 의견 수, 면접일지 수, 취업일(있으면), 지원고용 회차 상태(D에서 연결), 최근 적응지원 점검일. 버튼 "고용지원 화면으로".
3. **다음 할 일**: 기한 지남/오늘/이번 주 후속 일정. 완료 체크만 가능(체크는 입력이 아니라 상태 변경으로 허용). "일정 추가"는 고용지원 화면으로 이동.
4. **타임라인**: 모든 사례문서·상담·평가·훈련 기록을 날짜 역순 한 줄씩. 종류별 색 배지. 누르면 해당 화면의 그 문서로 이동.
5. **목표 진행 현황**: 목표별 최근 변화 기록 1줄 + 추이(기록 수, 마지막 날짜). 입력은 고용지원 화면.
6. **현재 상황 정리**: 담당자 메모 1개(저장 시각 표시) + "AI로 요약 초안 만들기"(위 카드 데이터를 비식별화해 보내고, 결과는 메모 칸에 넣기만 하며 자동 저장하지 않음).

### 기존 입력 폼의 이동
| 현재 현황판 섹션 | 이동할 곳 | 방법 |
|---|---|---|
| 후속 일정 추가·편집 | 고용지원 → 사례관리 문서 연속작성 단계 하단 "후속 일정" | `RehabWorkflow.tsx`의 tasks 폼을 `src/pages/workmate/FollowUpTasks.tsx`로 이동 |
| 목표 변화 추적 입력 | 고용지원 → 계획서 단계 "목표 변화 기록" | 동일 방식 |
| 취업 후 적응지원 점검 | 고용지원 → 새 탭 **"적응지원"** | `RehabExtensionSections.tsx`의 employment 부분 이동 |
| 직무 요구–지원 필요 비교 | 고용지원 → AI 정밀 매칭 탭 하단 | jobComparison 부분 이동 |
| 당사자 참여형 계획 확인 | 고용지원 → 계획서 단계 "당사자 확인" | participantPlan 부분 이동 |

이동한 폼은 같은 `RehabWorkflowData`를 읽고 쓰므로 기존 기록은 그대로 보인다. 현황판의 `useUnsavedGuard`는 메모 1개만 감시하게 되어 단순해진다.

### 전체 일정판(RehabDueBoard)
이용자를 고르기 전 화면으로 유지한다. 위쪽에 **전체 요약 4칸**(등록 이용자 수, 훈련 중, 지원고용 진행 중, 이번 주 기한 일정 수)을 추가하고, 아래에 기한 지난 일정 목록을 둔다.

### 파일 계획
- `src/pages/RehabWorkflow.tsx` → 대시보드 조립만(150줄 이내 목표)
- 새 폴더 `src/pages/overview/`: `SeekerHeader.tsx`, `StatusCards.tsx`, `NextActions.tsx`, `CaseTimeline.tsx`, `GoalProgress.tsx`, `SituationNote.tsx`, `useSeekerOverview.ts`(평가·훈련·고용지원 데이터를 한 번에 모으는 훅, 요청 ID로 늦은 응답 폐기)

## C. 예산 관리 신뢰성 점검

1차 수정에서 금액 재계산·음수 품목·CSV·확인창은 고쳤다. 이번에는 **숫자가 어디서나 같게 나오는지**를 기준으로 전체를 다시 본다.

### C-1. 계산 규칙을 한 곳으로
- `src/pages/budget/budgetUtils.ts`에 순수 함수로 통일: `expenseTotal(e)`, `projectSpent(project, expenses)`, `projectBalance`, `itemSpent`, `usageRate`, `isOverBudget`, `monthlyTotals`, `categoryTotals`.
- 화면(사업 카드, 세부 항목 뱃지, 지출 목록 합계, 지출품의서, CSV)이 **모두 이 함수만** 쓰는지 grep으로 확인하고, 직접 `reduce`하는 곳을 제거한다.
- 새 테스트 `scripts/test-budget-calc.mjs`: 부가세 포함/미포함, 수량×단가 반올림, 음수 품목, 사업 미지정 지출, 삭제된 사업의 지출, 항목 이동 후 잔액, 월 경계(KST) 합계.

### C-2. 저장 구조 안정화 (결정 필요)
- 현재 사업 예산은 `localStorage['jjss:budget-projects']`(용량 5MB, 트랜잭션 없음, 암호화 없음), 지출은 IndexedDB다. 두 저장소가 어긋나면 "사업은 있는데 지출 연결이 끊긴" 상태가 생긴다.
- **권장**: IndexedDB에 `budgetProjects` store를 추가(DB 버전 +1). 첫 실행 때 localStorage 값을 옮기고, 성공 후에만 localStorage 키를 삭제. 백업 JSON의 `budgetProjects` 필드는 그대로 유지해 옛 백업도 복원되게 한다.
- 이 항목은 기존 복구 원칙("DB 버전 변경 금지")과 충돌하므로 **사용자 결정** 후 진행. 결정 전까지는 localStorage 쓰기 실패(용량 초과) 시 오류 토스트와 백업 안내를 추가한다.

### C-3. 정합성 점검 기능
- 예산 화면 상단에 "정합성 점검" 버튼: 사업 없는 지출, 항목 없는 지출, 총예산 < 항목 합계, 지출일이 사업기간 밖, 중복 승인번호를 찾아 목록으로 보여 주고 각 행에서 바로 수정으로 이동.
- 지출품의서 미리보기의 합계와 지출 목록 합계가 다르면 출력 전에 경고.

### C-4. 입력 검증 보강
- 지출일 미래 날짜 경고, 사업기간 밖 날짜 경고(차단은 아님), 승인번호 중복 경고, 거래처 사업자번호 형식(000-00-00000) 검사.
- 부가세 자동 계산 옵션(공급가액의 10%, 반올림 규칙 명시) + 수동 입력 유지.

### C-5. 집계 화면
- 사업별·월별·예산과목별 집계 표와 간단한 막대(외부 라이브러리 없이 CSS). 집계는 C-1 함수만 사용.
- CSV 내보내기에 집계 시트 추가(두 번째 파일 또는 하단 요약 행).

## D. 지원고용 예산 자동 계산 + 결과보고 서류 자동 생성

### D-0. 서류에서 읽어낸 규칙 (2026년 기준, 연도별로 바뀔 수 있어 설정값으로 둔다)
| 항목 | 단가 | 적용 일수 | 수령인 |
|---|---|---|---|
| 훈련수당 | 35,000원/일 | 사전훈련 + 현장훈련 | 훈련생 |
| 사업주보조금 | 19,340원/일 | **현장훈련만** | 사업체 |
| 직무지도원수당 | 25,000원/일 | 사전훈련 + 현장훈련 | 직무지도원(내부/외부) |

검증: 사전 1일 + 현장 15일 → 훈련수당 560,000 / 보조금 290,100 / 지도원 400,000 / 계 1,250,100. 사전 1일 + 현장 14일 → 525,000 / 270,760 / 375,000 / 계 1,170,760. 두 사례 모두 첨부 서류와 일치.

서식 버전이 두 가지 섞여 있다(지급명세서: 별지 제9호 2021.12.30 개정 ↔ 붙임 28, 열 순서 다름). **템플릿을 연도·기관별로 교체할 수 있는 구조**가 필요하다.

### D-1. 데이터 모델 (새 IndexedDB store 1개: `supportedEmploymentCases`)
```
SupportedEmploymentCase {
  id, round(회차 번호), seekerId, jobId(사업체), 
  jobTitle(훈련직무), period { start, end, plannedEnd },
  plannedCount(계획인원, 기본 1),
  preTrainingDays(사전훈련 일수, 기본 1),
  coach { name, type: '내부'|'외부', phone, bank, account },   // 직무지도원
  traineePayee { bank, account },                              // 훈련생 송금계좌
  employerPayee { bank, account, phone },
  rates { trainingAllowance, employerSubsidy, coachAllowance, year },
  dailyLogs: [{ date, phase: '사전'|'현장', attendance: '출석'|'지각'|'조퇴'|'결석',
                start, end, commuteGuidance: boolean, task, performanceHours, note }],
  coachTimesheet: [{ date, start, end, hours, oneToMany: boolean, overtime: number }],
  evaluation { pre: number[20], field: number[20], opinions: { attitude, relations, workAttitude, performance } },
  result { completed: boolean, employed: boolean, employmentDate, note },
  status: '진행중'|'수료'|'중단'|'취업',
  budgetProjectId?, expenseIds?: string[]   // 예산 연동
}
```
- 계좌번호·연락처는 `SENSITIVE_FIELDS`에 넣어 암호화 저장. 백업에도 암호화 백업 사용을 권장 문구로 안내.
- 이용자(`seekers`)·사업체(`jobs`)는 기존 데이터를 참조하고, 직무지도원은 회차에 귀속(같은 사람을 다음 회차에 "이전 지도원 불러오기"로 복사).
- `caseDocuments`에 `type: 'supported_employment'` 요약 문서를 함께 저장해 현황판 타임라인·고용지원 이력에 보이게 한다.

### D-2. 화면: 고용지원 → 새 탭 **"지원고용 관리"**
1. **회차 목록**: 회차·이용자·사업체·기간·상태·계(원). "새 회차" 버튼.
2. **회차 등록**: 이용자·사업체 선택(기존 목록), 훈련직무, 기간(달력에서 시작·종료 고르면 **주말·공휴일 제외 훈련일 자동 생성**, 사전훈련 일수 지정), 직무지도원, 계좌 정보, 단가(연도별 기본값 자동, 수정 가능).
3. **훈련일지 입력**: 생성된 날짜 표에서 출석·시간·과제·수행정도·지도사항을 행마다 입력. "이전 행 복사", "전체 출석 처리", 결석일은 수당에서 자동 제외. 지도원 출근부는 훈련일지 시간에서 기본값을 채우고 수정 가능.
4. **종합 평가기록부**: 20개 항목 × 사전/현장 점수(1~5) + 영역별 소견 4칸. 총점 자동. "AI로 소견 초안"은 훈련일지 지도사항을 비식별화해 보내고 결과는 칸에 채우기만 한다.
5. **수당 계산 카드(항상 표시)**: 사전/현장/계 일수, 항목별 금액, 총계. 계산식이 보이게("35,000 × 16일").
6. **결과보고 출력**: 아래 서류를 묶음 또는 개별로 DOCX·PDF 저장. 출력 전 체크리스트(계좌 누락, 결석일 처리, 평가 미입력, 서명란 안내).

### D-3. 생성 서류 5종
| 서류 | 데이터 | 구현 방식 |
|---|---|---|
| ① 결과보고(표지) | 훈련개요·훈련결과·수당지급내역 | `docx` 라이브러리로 표 생성 |
| ② 지원고용 수당 지급명세서 | 3행(훈련수당·사업주보조금·직무지도원) + 계 | `docx`, 서식 버전(별지 9호 / 붙임 28) 선택 |
| ③ 지원고용 훈련일지 | 머리 정보 + 일자별 행(페이지 넘김) | `docx` 동적 행 |
| ④ 훈련생 종합 평가기록부 | 20항목 점수·소견·총점 | `docx` 고정 표(별지 4호) |
| ⑤ 직무지도원 출근부 | 주 단위 근무 상황표 | `docx` 주간 격자 |

- 기존 `rehabPlanDocx.ts`는 JSZip 토큰 치환 방식이라 **행 수가 변하는 표**에 맞지 않는다. 이미 의존성에 있는 `docx` 패키지로 프로그램 생성한다. 글꼴은 "맑은 고딕" 지정.
- PDF는 기존 `savePdf`(Electron 인쇄 창) 경로로 HTML 렌더 → PDF. DOCX와 같은 데이터 모델에서 HTML을 만들어 미리보기에도 쓴다.
- 서명·직인 칸은 비워 두고 출력 후 수기. 담당자 이름은 설정의 담당자 프로필(1차에서 훈련 상태에 넣은 값을 설정으로 승격)에서 채운다.
- 파일명: `지원고용_결과보고_14차_2026-08-19.docx`처럼 **이용자명 미포함**(개인정보 파일명 정책 유지).

### D-4. 예산 연동
- 회차를 "수료/취업"으로 확정하면 예산 관리에 지출 3건(훈련수당·사업주보조금·직무지도원수당)을 **초안으로 생성**할지 묻는다. 사업(`budgetProject`)은 "지원고용" 사업을 고르게 하고, 세부 항목은 3가지에 자동 매핑.
- 회차 수정으로 금액이 바뀌면 연결된 지출 초안에 "회차 금액과 다름" 표시. 자동 덮어쓰지 않는다.
- 연도 단가표는 설정 > 지원고용 단가에서 관리(연도별 행 추가). 회차 생성 시점의 단가를 회차에 복사해 두어 나중에 단가가 바뀌어도 과거 서류가 변하지 않게 한다.

### D-5. 반복 업무 줄이기
- **다음 회차 복사**: 같은 사업체·지도원으로 새 회차 만들 때 계좌·직무·단가 복사.
- **훈련일지 기본값**: 시간·과제는 첫 행 입력 후 아래 행에 자동 복사, 지도사항만 바꾸면 됨.
- **출근부 자동 작성**: 훈련일지 시간으로 지도원 출근부를 채우고 총 지도시간 계산.
- **묶음 출력**: 5종을 한 번에 저장(폴더 하나에 번호 붙여). 결과보고 4종 / 전체 5종 선택.
- **현황판 연동**: B의 고용지원 카드에 "지원고용 14차 진행 중 · 현장 12/15일 · 예정 지급액 ○○원" 표시.

### D-7. 결정 사항 (2026-09-24 확정)
1. **새 IndexedDB store**: 미결. D는 store를 새로 만들지 않고 `caseDocuments`에 `type: 'supported_employment'` 문서로 회차 전체를 JSON으로 저장한다(content는 기존 암호화 대상이므로 계좌·연락처가 함께 암호화됨). 따라서 D는 DB 버전 변경 없이 진행 가능하다. C-2(사업 예산 IndexedDB 이관)만 결정을 기다린다.
2. **출결 규칙**: 결석은 해당일 미지급. **지각·조퇴 3회 = 결석 1회**로 환산해 지급 일수에서 뺀다(3회 미만은 전액). 환산 내역을 수당 카드에 표시한다. 예: 지각 4회 → 결석 1회 환산, 남은 1회는 다음 환산까지 누적 표시.
3. **공휴일**: 고정 공휴일 + **대체공휴일**(설·추석·어린이날·3·1절·광복절·개천절·한글날 규칙)을 내장하고, 기관 휴무는 회차 등록 시 직접 제외한다. 공휴일표는 연도별 설정으로 두어 수정 가능하게 한다.
4. **지급명세서 서식**: **한 가지**로 통일(최신 별지 제9호 2021.12.30 기준 열 순서: 구분 / 성명(사업장명) / 수령인(송금계좌번호) / 연락처 / 지급명세 / 금액). 붙임 28 선택 기능은 만들지 않는다.
5. **계좌번호**: 회차에 **암호화 저장**한다(로컬 PC, AES-GCM + DPAPI 키). "다음 회차 복사"로 재입력을 줄인다. 저장하지 않고 매번 입력하는 옵션은 만들지 않는다.
