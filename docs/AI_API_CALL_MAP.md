# JJSS AI API 호출 지도

기준일: 2026-08-17

공통 원칙은 사용자의 명시적인 버튼 실행 1회당 AI Job 1개입니다. 자동 retry는 0회이며, 텍스트 failover를 켠 경우에도 Provider당 1회, Job당 최대 3회입니다. 이미지 생성과 직업평가 전용 분석은 Gemini 1회만 호출합니다.

| 기능 | 사용자 Trigger | 정상 호출 수 | Failover 최대 호출 | 자동 Retry |
|---|---|---:|---:|---:|
| 직업재활계획서 | 생성/보완 버튼 | 1 | 3 | 0 |
| 상담일지 | 생성/보완 버튼 | 1 | 3 | 0 |
| 사례회의 | 생성/보완 버튼 | 1 | 3 | 0 |
| 정기평가 | 생성/보완 버튼 | 1 | 3 | 0 |
| 작성내용 점검 | 수행방법 반영 점검 버튼 | 1 | 3 | 0 |
| AI 정밀매칭 | 매칭 실행은 로컬 계산, 의견 보완 버튼만 AI | 0 또는 1 | 3 | 0 |
| 면접일지 | 생성/보완 버튼 | 1 | 3 | 0 |
| 직무분석 | 생성/보완 버튼 | 1 | 3 | 0 |
| 직업평가 결과분석 | 결과 분석 버튼 | 1 (Gemini) | 1 | 0 |
| 종합소견서 | 종합보고서 생성 버튼 | 1 (Gemini) | 1 | 0 |
| PDF/이미지 문서 분석·질의응답 | 질문 전송 버튼 | 1 | 3 | 0 |
| 직업훈련 AI 문서 | 각 문서 생성/보완 버튼 | 1 | 3 | 0 |
| 공문 | 생성 버튼 | 1 | 3 | 0 |
| 회의록 | 회의록 생성 버튼 | 1 | 3 | 0 |
| 쉬운 글 | 변환 버튼 | 1 | 3 | 0 |
| 보도자료 | 생성 버튼 | 1 | 3 | 0 |
| 블로그 | 생성 버튼 | 1 | 3 | 0 |
| 홍보문구 | 생성 버튼 | 1 | 3 | 0 |
| OCR(PDF) | 파일 선택 후 OCR/분석 버튼 | 1 (Gemini) | 1 | 0 |
| OCR(이미지) | 파일 선택 후 OCR/분석 버튼 | 1 (Vision), 실패 시 Gemini 1 | 2 | 0 |
| 영수증 품목 정밀 파싱 | 예산 화면 OCR 실행 버튼의 후속 단계 | 1 (Gemini, 키가 있을 때) | 1 | 0 |
| 개인정보 비식별화 | 비식별화 실행 버튼 | 1 | 3 | 0 |
| 이미지/포스터/일정표 생성 | 이미지 생성 버튼 | 1 (Gemini) | 1 | 0 |
| API 키·모델·Provider 저장 | 설정값 변경 | 0 | 0 | 없음 |
| 문서 저장·복사·백업 | 저장/복사/백업 버튼 | 0 | 0 | 없음 |
| PDF·PNG·DOCX·CSV 출력 | 각 출력 버튼 | 0 | 0 | 없음 |

파일 선택은 파일명 표시와 로컬 읽기만 수행합니다. OCR은 별도의 분석 버튼을 눌러야 시작합니다. 화면 이동으로 Job이 취소되면 다음 Provider failover를 시작하지 않습니다.

개발 계측에는 Job ID, featureKey, Provider, 모델, 시도 횟수, 실행 시간만 사용합니다. prompt, 이용자명, 상담내용, API 키, 응답 전문은 기록하지 않습니다. 일일 카운터에는 날짜, Provider별 횟수, 일반 실행/연결 테스트 구분만 저장할 수 있으며 현재 연결 테스트 자동 실행 경로는 없습니다.
