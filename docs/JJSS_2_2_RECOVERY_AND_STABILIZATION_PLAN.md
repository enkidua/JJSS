# JJSS 2.2 복구 및 안정화 계획

작성일: 2026-05-08

## 1. 현재 상황 요약

JJSS는 2.2 버전 이후 여러 기능 추가와 롤백 과정에서 일부 기능이 사라지거나 불안정해진 상태입니다. 특히 직업평가 PDF 분석, 이미지 생성, API 키 저장, 기존 문서 표시, 고용지원/직업훈련/직업평가 문서 재생성 흐름이 영향을 받았습니다.

현재 확보한 복구 기준 자료는 다음과 같습니다.

- 현재 개발 프로젝트: `/Users/jeonghunkim/Desktop/dev/JJSS prod`
- exe 추출 복구본: `/Users/jeonghunkim/Desktop/JJSS_recovered_minimal`
- 핵심 번들 파일: `/Users/jeonghunkim/Desktop/JJSS_recovered_minimal/dist/assets/index-D6j7ox8t.beautified.js`
- 2.2 앱/설치 파일: `release/JJSS Setup 2.2.exe`, `release/JJSS Setup 2.2.app`

중요한 한계:

- exe에는 원본 `src/*.tsx` 파일이 들어 있지 않습니다.
- 대신 Vite로 빌드된 React 앱 로직이 `index-D6j7ox8t.beautified.js`에 합쳐져 있습니다.
- 따라서 원본 파일 구조를 자동으로 100% 복원하는 것은 어렵지만, 기능 로직은 번들에서 읽어 현재 소스에 다시 이식할 수 있습니다.

## 3. 복구 원칙

1. 기존 2.2 기능을 최대한 살립니다.
2. 2.2 이후 추가한 기능은 무조건 버리지 않고, 실제 사용 가치가 있는지 판단한 뒤 정리합니다.
3. 아직 구현되지 않은 버튼이나 흐름은 사용자에게 혼란을 주므로 숨기거나 삭제합니다.
4. Gemini 3, Gemini 3.1 기반으로 작동 가능한 기능은 가능한 한 유지합니다.
5. 임의로 모델을 낮추는 폴백은 최소화합니다.
6. 다만 PDF 분석처럼 특정 모델에서만 안정적으로 작동하는 기능은 사용자에게 명확히 안내하고 기능 단위 모델 고정을 검토합니다.
7. 저장 데이터는 절대 날리지 않는 것을 최우선 원칙으로 둡니다.
8. 기능 추가보다 먼저 저장소, API 키, 기존 문서 표시, 오류 알림을 단단하게 만듭니다.

## 4. 1차 복구 대상

### 4.1 저장소와 데이터 복구

목표:

- API 키가 안정적으로 저장되고 다시 불러와져야 합니다.
- 기존 이용자, 사업체, 문서가 앱 업데이트 후에도 계속 보여야 합니다.
- IndexedDB 버전 변경으로 기존 데이터가 사라진 것처럼 보이는 문제를 막아야 합니다.

점검 항목:

- `src/config/localDB.ts`
- `src/config/crypto.ts`
- `src/store/settingsStore.ts`
- `src/store/dataStore.ts`

필수 처리:

- IndexedDB 버전과 object store 목록 정리
- 기존 plaintext 데이터와 encrypted 데이터 모두 읽을 수 있는 호환 처리
- API 키 저장/복호화 실패 시 복구 안내
- 기존 `caseDocuments` 필터링 기준 통일
- seekerId/id 혼용 문제 정리

### 4.2 직업평가 PDF/이미지 분석 복구

목표:

- PDF, JPG, PNG 업로드 후 분석이 멈추지 않아야 합니다.
- 오류가 생기면 계속 로딩하지 말고 명확한 메시지를 보여야 합니다.
- 2.2 기준의 `files.upload()` 후 실패 시 `inlineData` fallback 구조를 복원합니다.

기준 로직:

- 복구본 `index-D6j7ox8t.beautified.js`의 `yU` 함수 영역
- 현재 `src/services/gemini.ts`의 `analyzeTestResults`
- 현재 `src/pages/VocationalEvaluation.tsx`

검토할 모델 정책:

- 기본은 사용자가 선택한 Gemini 모델을 존중합니다.
- 단, PDF 분석이 Gemini 2.5 Flash에서만 안정적인 경우 직업평가 분석만 별도 모델 고정을 검토합니다.
- 이 경우 UI에 "직업평가 문서 분석은 안정성을 위해 Gemini 2.5 Flash를 사용합니다"처럼 안내합니다.

### 4.3 이미지 생성 복구

목표:

- 이미지 생성이 무한 로딩으로 멈추지 않아야 합니다.
- 이미지 모델명을 2.2 기준으로 복원하거나, 현재 Gemini 문서 기준으로 작동 가능한 모델만 허용합니다.
- 강한 한국어 텍스트 프롬프트는 유지합니다.

기준 로직:

- 복구본 `Dg` 함수
- 현재 `src/services/gemini.ts`의 `generateImage`
- `src/components/PromoDesignView.tsx`
- `src/components/ScheduleDesignView.tsx`

모델 정책:

- 기본 이미지 생성 모델은 안정성을 우선합니다.
- 사용자가 원한 원칙에 따라 Gemini 3/3.1 기반 모델이 실제 작동하면 유지합니다.
- 모델명 오류나 API 미지원으로 실패하는 경우는 사용자에게 구체적으로 안내합니다.
- 무료 API 제한, 모델 권한 제한, preview 모델 부하 가능성은 오류 메시지에 반영합니다.

## 5. 2차 기능 복구 및 정리

### 5.1 인트라넷 제거

현재 인트라넷은 사용자가 직접 구현하지 못한 상태이므로 일단 앱에서 제거합니다.

처리 방향:

- 메인 화면 또는 메뉴에서 인트라넷 진입 제거
- `WelfareLauncher` 관련 route/nav 제거
- 관련 코드 파일은 바로 삭제하지 않고, 복구 브랜치에서는 보관 여부 판단 후 정리
- 나중에 Google Drive 기반 설치형 인트라넷이 안정화되면 별도 기능으로 재추가

### 5.2 예산 화면 정리

사용자가 지적한 “예산 바로 밑에 예산을 통으로 입력하는 화면”은 실제 사용처가 적절한지 확인합니다.

판단 기준:

- 예산/지출 관리에 실질적으로 필요한 입력인지
- 아래 지출 등록 기능과 중복되는지
- 데이터 저장, 조회, 출력 흐름에 연결되어 있는지

처리 방향:

- 연결되지 않았거나 중복이면 삭제
- 지출 등록, 지출품의서, 지출 목록 중심으로 단순화
- 예산 요약 카드가 빈 데이터에서 의미가 없다면 축소 또는 숨김

### 5.3 고용지원 매칭 결과 정리

현재 매칭 결과의 `이력서 보기`, `파일 생성` 버튼은 미구현 기능이면 삭제합니다.

대신 강화할 부분:

- `AI Recommendation & Profile` 영역을 더 풍부하게 작성
- 단순 프로필 요약이 아니라 다음 항목을 포함:
  - 추천 사유
  - 직무 적합성
  - 강점
  - 우려점
  - 사업체 배려사항
  - 초기 적응 지원계획
  - 담당자 확인 체크포인트

## 6. 문서 재생성 기능 확장

사용자가 만족한 “사례회의 재생성” 방식은 다른 사례 관련 문서 작성 흐름에도 확장합니다.

핵심 UX:

- AI가 초안을 생성합니다.
- 사용자가 초안을 직접 수정합니다.
- `재생성`을 누르면 현재 수정된 내용을 기준으로 다시 보완 생성합니다.
- 기존 작성 내용을 덮어쓰기 전에 확인하거나, 이전 버전을 기록으로 남깁니다.

적용 대상:

- 고용지원
  - 사례회의
  - 직업재활계획서
  - 상담일지
  - 정기평가
  - 면접일지
- 직업훈련
  - 훈련계획
  - 상담일지
  - 정기평가
  - 성과/공유 기록
- 직업평가
  - 결과분석
  - 종합소견서

원칙:

- 사용자의 수정본을 가장 중요한 context로 사용합니다.
- 이전 기록과 이용자 기본정보를 함께 넣습니다.
- “완전히 새로 작성”과 “현재 초안 보완”을 구분합니다.
